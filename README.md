Локальный HUD-оверлей для **R.E.P.O.**, который показывает информацию о текущем забеге в отдельном прозрачном окне поверх игры.

## Что делает мод

OverlayHUD состоит из BepInEx-плагина и комплектного desktop-приложения. После запуска modded-версии игры плагин автоматически распаковывает и запускает приложение, синхронизирует с ним состояние текущего забега, а при выходе из игры закрывает его.

HUD умеет показывать:

- встреченных монстров и их уровень силы;
- текущее и максимальное здоровье монстров;
- состояние монстра и оставшееся время до респавна;
- номер уровня и таймер прохождения;
- улучшения игрока;
- текущую стоимость ценностей на карте;
- потерянную стоимость ценностей;
- кто последним держал предмет, упавший в пропасть и уничтоженный;
- отдельные timestamps прохождения уровней.

Монстры не раскрываются заранее. Плагин знает состав уровня для внутренней синхронизации статусов, но добавляет монстра в видимую часть HUD только после того, как игра зафиксировала встречу с ним.

## Возможности оверлея

### Экспериментальный HUD внутри игры

Режим `Native` рисует HUD через Unity Canvas вместо Electron: не запускает
desktop-приложение и не отправляет HTTP-запросы. После сборки замените
`OverlayHUD.dll` в профиле мода и настройте `BepInEx/config/local.overlay.overlay_hud.cfg`.
Ниже полный пример Native-настроек с исходными значениями; только `Renderer`
изменён с `Electron` (по умолчанию) на `Native`:

```ini
[Overlay]
Renderer = Native

[NativeHUD]
Enabled = true
Language = ru
SaveTimestamps = true
UseGameUIEffects = false
Scale = 1
Alignment = Center
OffsetX = 0
OffsetY = 20
HorizontalLayout = true
HorizontalColumns = 11
Columns = 4
MonsterSize = 70
UpgradeSize = 38
UpgradeRows = 2
WrapValueLabels = true
ShowLevel = true
ShowTimer = true
ShowMapValue = true
ShowLostValue = true
ShowMonsters = true
ShowHealth = true
ShowRespawnTimer = true
ShowRespawnIndicator = true
ShowStrength = true
ShowMonsterCounts = true
ShowUpgrades = true
ShowProximityWaves = true
ShowDamageNumbers = true
Animations = true
ShowDestroyedItemAlerts = true
ShowTooltips = false
OnlyAliveMonsters = false
FilterUndetectedMonsters = false

[NativeHUD.Upgrades]
strength = true
tumbleLaunch = true
range = true
sprintSpeed = true
tumbleWings = true
crouchRest = true
extraJump = true
tumbleClimb = true
health = true
stamina = true
mapPlayerCount = true
deathHeadBattery = true
```

**Только `Renderer` требует перезапуска игры.** Все параметры `[NativeHUD]` и
`[NativeHUD.Upgrades]`, включая компоновку и колонки, применяются на лету через
BepInEx Configuration Manager или перезагрузку конфига средствами BepInEx.
Автоматического наблюдения за cfg-файлом нет: ручное редактирование требует
перезагрузки конфига либо игры. `Renderer = Electron` возвращает desktop-интерфейс;
при ошибке создания Canvas/загрузки ресурсов плагин пишет причину в лог и
возвращается к Electron на текущую сессию.

**Компоновка и размеры**

| Параметр | Назначение |
| --- | --- |
| `HorizontalLayout` | `true` — компактная верхняя строка, монстры используют `HorizontalColumns`; `false` — верхние блоки переносятся по ширине сетки, используется `Columns`. **В обоих режимах** лишние монстры переходят на следующий ряд, а не скрываются. |
| `HorizontalColumns` / `Columns` | Максимум плиток в ряду: 1–24, по умолчанию 11 / 4. Неактивный для текущего режима параметр игнорируется. |
| `Alignment` | `Left`, `Center`, `Right`: привязка всей панели к левому краю, центру или правому краю экрана, а также выравнивание содержимого шапки и рядов монстров. |
| `OffsetX` / `OffsetY` | Смещение от выбранной горизонтальной привязки (плюс — вправо, −1920…1920) / отступ сверху (0–1080), в масштабируемых пикселях HUD. Положение ограничено краями экрана с полями. |
| `Scale` | 0.5–2; `1` — базовый размер при 1920×1080. Масштаб учитывает обе стороны окна (`min(width/1920, height/1080)`), затем ограничивается размерами панели. Это устраняет лишнее увеличение на 16:10 и 4:3. DPI/zoom и сохранённые настройки Electron всё ещё могут давать отличия. |
| `MonsterSize` / `UpgradeSize` | Размер плитки монстра 32–128 / иконки улучшения 20–64 до общего масштаба; по умолчанию **70 / 38 px**. Улучшения сохраняют пропорции (при 38 px область вписывания — 31.16 × 38 px). |
| `UpgradeRows` | 1 или 2 ряда улучшений, по умолчанию 2 сбалансированных; сортировка по количеству. В узкой сетке возможны дополнительные переносы. |
| `WrapValueLabels` | `true` — подписи карты/потерь над суммами; `false` — в одной строке с ними. |

**Видимость и эффекты** (все переключатели этой таблицы по умолчанию `true`)

| Группа | Переключатели и действие |
| --- | --- |
| Весь HUD | `Enabled` скрывает HUD, не останавливая отслеживание игрового состояния и запись timestamps. |
| Верхняя панель | `ShowLevel`, `ShowTimer`, `ShowMapValue`, `ShowLostValue` независимо показывают уровень, таймер, цену карты и потери. Таймер поддерживает часы; нулевые суммы скрыты. |
| Монстры | `ShowMonsters` скрывает только плитки, не шапку/улучшения; `ShowMonsterCounts` управляет счётчиками групп. |
| Здоровье | `ShowHealth` управляет **полосками** ХП. Числа текущего/максимального ХП доступны в подсказках независимо от этого переключателя. |
| Респавн | `ShowRespawnTimer` — числовой отсчёт `м:сс`; `ShowRespawnIndicator` — круговой сектор оставшегося времени. Независимы друг от друга; неизвестный/истёкший отсчёт не висит как `00:00`. |
| Сила | `ShowStrength` — требуемое число улучшений у обнаруженных монстров, **включая респавн**. Зелёный — силы хватает, красный — нет; янтарные `X` — поднять нельзя, `?` — данных нет. |
| Улучшения | `ShowUpgrades` — полученные улучшения с количеством; каждый из 12 ключей `[NativeHUD.Upgrades]` отдельно включает/скрывает свой тип. Нулевые количества скрыты. |
| Эффекты | `ShowProximityWaves` — волны близости; `ShowDamageNumbers` — всплывающий урон. `Animations = false` отключает переходы, волны, вспышки и числа урона; числовые таймеры продолжают обновляться. |
| Уведомления | `ShowDestroyedItemAlerts` — уничтоженный предмет и последний державший его игрок. |

**Язык, подсказки и фильтры**

| Параметр | Поведение |
| --- | --- |
| `Language = ru` | Русские подписи по умолчанию; `en` — английские. Исходные имена монстров, игроков и предметов не переводятся. |
| `ShowTooltips = false` | При `true` наведение на обнаруженного монстра известного вида показывает имя, ХП и силу, на улучшение — локализованное название. Работает **только с разблокированным игровым курсором**: HUD не разблокирует и не захватывает его, не перехватывает клики. Подсказки удерживаются в пределах экрана. |
| `OnlyAliveMonsters = false` | При `true` скрывает погибших обнаруженных монстров до респавна; необнаруженные заглушки по умолчанию сохраняются. |
| `FilterUndetectedMonsters = false` | Действует **только вместе с `OnlyAliveMonsters = true`**: дополнительно удаляет погибшие необнаруженные заглушки. Живые необнаруженные остаются; сам по себе параметр ничего не фильтрует. |

Необнаруженные монстры остаются заглушками без раскрытия вида, ХП и состояния.
Группы объединяются в плитки (`x4` гномов, `x3` Banger), несколько полных групп —
в отдельные плитки; обычные одиночные монстры не объединяются. ХП группы суммируются,
счётчик отражает полученные экземпляры, группа жива, пока жив хотя бы один участник;
после гибели всех показывается ближайший известный респавн. До встречи — одна
заглушка без счётчика. Сила вычисляется из игровых параметров захвата, не из таблицы
имён: для группы берётся максимальное известное требование, невозможность поднять
хотя бы одного участника даёт `X`.

Карточки сортируются по игровому тиру; рамки зелёные, синие, красные, при неизвестном
тире — золотистые. Есть свечение по силуэту, тени, плавное появление и смена изображения,
анимация ХП, вспышки и числа урона. Полоска ХП меняет цвет при 60%, 30% и 10%;
сокращение респавна выделяется красным, волны ускоряются при очень близком монстре.
Блик неизвестного вида появляется только после обнаружения, не на скрытых слотах.

Уведомление об уничтожении показывается **6 секунд**, новое заменяет предыдущее
без очереди. При отключённых уведомлениях события считаются обработанными и не
воспроизводятся после включения; скрытие HUD не приостанавливает их срок.
Смена уровня сбрасывает уведомление. Оно размещается над/под панелью и ограничивается
экраном даже при крайних смещениях; длинный текст сокращается.

**Локальные timestamps**

`SaveTimestamps = true` сохраняет отдельный UTF-8 `.txt` на сессию в
`BepInEx/plugins/OverlayHUD/timestamps` (имя файла — локальные дата/время).
Записываются локальное время начала, номер уровня, название карты, имена и количества
встреченных монстров; **имена игроков модуль записи не сохраняет**, данные никуда не загружаются.
`false` завершает текущую запись и останавливает дальнейшую; после включения запись
возобновляется **со следующего уровня**, без восстановления пропущенных уровней.

**Штатные эффекты игрового HUD (экспериментально)**

`UseGameUIEffects = true` выводит Native через отдельную UI-камеру игры: она применяет
свои искривление линзы, хроматическую аберрацию и bloom, как к родному HUD. По умолчанию
`false` оставляет независимый чёткий оверлей. Переключение применяется без перезапуска.
Это не новый шейдер: профиль эффектов, материалы, камеры и текстуры игры не изменяются.

- При включении используются пропорции и область игрового HUD, в том числе на ultrawide;
  масштаб и положение могут немного отличаться от независимого оверлея.
- Резкость ограничена разрешением UI-текстуры игры: текст может стать мягче/пиксельнее.
- Hover-подсказки временно отключаются: обычные координаты курсора не учитывают искривление.
- Если игровая UI-камера недоступна, Native возвращается к обычному выводу и повторяет
  подключение раз в 0.5 секунды; после смены сцены подключается к новым объектам.
- В логе BepInEx сообщения `Native HUD game UI effects active/unavailable/disabled`
  показывают текущий режим. Визуальное действие эффекта требует проверки в игре.

**Ограничения и проверки**

Иконки и растровые атласы Teko с утолщённым начертанием, Roboto Bold/ExtraBold
встроены в DLL; установка шрифтов не нужна. Подписи «УРОВЕНЬ», «КАРТА», «ПОТЕРЯ»
используют кириллицу из Teko в тех же размерах, что английские подписи в Electron;
Roboto остаётся у бейджей, подсказок и уведомлений. Набор глифов ограничен ASCII и частью кириллицы (U+0400–U+045F):
символы вне доступного атласа, включая многие не-ASCII символы и расширенную кириллицу,
заменяются на `?`, системного шрифтового fallback нет. При увеличении текст может быть
мягче браузерного; Unity Canvas и растровые шрифты не гарантируют попиксельного совпадения.

Ещё не перенесены drag-and-drop, web-панель настроек, трей и скриншоты; импорта
сохранённых настроек браузера нет. Native настраивается собственным конфигом.
Скрытие при карте и счётчике квоты сохранено; в Native квота скрывает HUD
**при любых смещениях**, не только у верхнего края.

Команды из корня репозитория:

- Пересборка ресурсов: `uv run --with pillow python tools/build-native-assets.py`.
- Сборка плагина: `dotnet build overlay-hud/OverlayHUD.csproj -c Release`.
- Проверки состояния, событий и вспомогательной логики Native: `dotnet run --project tests/native-hud/NativeHud.Tests.csproj`.

Эти проверки не заменяют реальный забег: отображение, курсор и совместимость
с игровым UI требуют отдельной runtime-проверки.

### Desktop HUD

- прозрачное окно поверх игры;
- пропуск кликов сквозь окно;
- перетаскивание и привязка к краям или центру экрана;
- изменение общего масштаба и отдельного масштаба улучшений;
- настройка количества колонок с монстрами;
- одинарная или двойная строка улучшений;
- русский и английский интерфейс;
- включение и отключение отдельных элементов HUD;
- настройка фоновой панели и прозрачности при наведении;
- появление HUD и запуск таймера после загрузки, когда игрок получает управление;
- скрытие HUD на время просмотра карты (включая анимацию закрытия, независимо от назначенной клавиши);
- скрытие HUD во время показа счётчика денег `CurrencyUI` при сдаче квоты, только если HUD примагничен к верхнему краю экрана; нижняя, центральная и свободная позиции не скрываются;
- сохранение пользовательских настроек между запусками.

Для desktop-оверлея доступны глобальные горячие клавиши:

| Сочетание | Действие |
| --- | --- |
| `Ctrl+Alt+O` | Показать или скрыть окно |
| `Ctrl+Alt+I` | Включить или выключить пропуск кликов |
| `Ctrl+Alt+R` | Перезагрузить страницу оверлея |
| `Ctrl+Alt+Q` | Закрыть OverlayHUD |

Те же действия доступны через значок OverlayHUD в системном трее.

## Как это работает

```mermaid
flowchart LR
    Game["R.E.P.O."] --> Plugin["OverlayHUD.dll<br/>BepInEx + Harmony"]
    Plugin -->|"HTTP JSON<br/>127.0.0.1:8787"| Server["Локальный Node.js server"]
    Server -->|"State + Server-Sent Events"| Web["HTML / CSS / JavaScript HUD"]
    Web --> Electron["Прозрачное Electron-окно"]
```

### Игровой плагин

`overlay-hud/Plugin.cs` загружается через BepInEx и с помощью Harmony подписывается на игровые события:

- генерацию и смену уровня;
- создание, исчезновение и респавн врагов;
- события видимости и близости монстров;
- изменение здоровья монстров;
- получение улучшений;
- изменение, разрушение и сдачу ценностей.

Большая часть синхронизации событийная. Периодические проходы используются только как страховка, а reflection-метаданные, источники здоровья и результаты проверок компонентов кэшируются, чтобы снизить нагрузку на Unity.

### Локальный сервер

`server.js` хранит состояние HUD и принимает обновления от плагина через локальные `/api/...` endpoints. Страница оверлея получает новые состояния через Server-Sent Events и не выполняет постоянный тяжёлый polling.

В packaged-приложении сервер слушает только `127.0.0.1:8787`: данные не отправляются во внешний интернет, телеметрии нет.

> При ручном запуске через `start-server.bat` используется стандартный host из `server.js` — `0.0.0.0`. Такой режим может открыть порт `8787` в локальной сети. Для обычной установки через r2modman это не используется.

### Desktop-приложение

`game-overlay/main.js` создаёт прозрачное click-through окно Electron, запускает встроенный сервер и открывает `http://127.0.0.1:8787/overlay.html`.

Во время загрузки уровня и вне активного игрового уровня приложение скрывает само прозрачное окно, а не только содержимое HUD, и останавливает проверки наведения курсора. Для скрытого окна разрешено фоновое ограничение активности Chromium. Локальный сервер и получение состояния продолжают работать, поэтому HUD возвращается автоматически после загрузки; ручное скрытие через трей или хоткей сохраняется до повторного включения. Для этого поведения нужно обновить desktop-приложение вместе с веб-ресурсами; DLL менять не требуется.

Архив `OverlayHUD_app.zip` остаётся рядом с DLL мода. По умолчанию плагин устанавливает и запускает приложение вне каталога мода:

```text
%LOCALAPPDATA%\OverlayHUD\profiles\<profile-key>\app\OverlayHUD.exe
```

`<profile-key>` — SHA-256 нормализованного `BepInExRootPath`. Файлы приложения, корневой `overlay-config.json` и `timestamps/` изолированы по профилям BepInEx. Настройки web-панели в Electron `localStorage` остаются в прежнем хранилище Electron: изоляция браузерных профилей не меняется.

## Установка через r2modman

1. Откройте r2modman, выберите R.E.P.O. и создайте или выберите профиль.
2. В настройках профиля (`Settings`) найдите `Import local mod` и выберите архив `EgorSalad-OverlayHUD-<version>.zip`. Предварительно распаковывать ZIP не нужно.
3. Убедитесь, что в профиле установлен BepInExPack.
4. Запустите игру через кнопку `Start modded` в r2modman.
5. При первом запуске дождитесь распаковки и автоматического старта `OverlayHUD.exe`.

Node.js и Electron отдельно устанавливать не требуется: desktop-приложение уже находится внутри пакета.

### Перенос и обновление desktop-приложения

Перед обновлением или подготовкой к переносу закройте **игру и OverlayHUD**. Не удаляйте старую папку `OverlayHUD_app` рядом с DLL: при следующем desktop-автозапуске (`OverlayApp.AutoStart=true`) плагин скопирует распознанную старую установку во внешнюю папку целиком, включая `overlay-config.json`, `timestamps/` и неизвестные файлы. Обновление из архива применяется с сохранением корневого конфига и timestamps; старая папка удаляется только после успешного переноса. Native HUD не запускает перенос, его timestamps остаются на прежнем месте.

Если старая и внешняя установки уже существуют одновременно, старая остаётся нетронутой, а лог предупреждает о необходимости ручной проверки. Если удалению после переноса мешают заблокированные файлы, плагин также пишет предупреждение.

Изменение SHA-256 архива автоматически запускает обновление через промежуточную папку: вручную удалять приложение не нужно. При ошибке исходная установка сохраняется, запуск отменяется. Для самого переноса достаточно обновлённой DLL и существующего `OverlayHUD_app.zip`; пересборка Electron не требуется.

Внешние файлы сохраняются после удаления мода или профиля в менеджере модов. Для полной очистки закройте приложение, сохраните нужные `timestamps/` и `overlay-config.json`, затем вручную удалите соответствующую папку `%LOCALAPPDATA%\OverlayHUD\profiles\<profile-key>`.

### Режим отображения игры

Используйте оконный или borderless-режим. Обычное desktop-окно не может отображаться поверх игры в exclusive fullscreen.

Скрытие при сдаче квоты зависит только от привязки HUD к верхнему краю (`anchorY: top`), а не от координат `CurrencyUI`. Исходное положение без ручного перемещения также считается верхним. Горизонтальная привязка не влияет на это правило. При открытии карты HUD скрывается в любом положении. Для новой логики нужны обновлённые DLL и desktop-приложение.

## Конфигурация

После первого запуска BepInEx создаёт файл:

```text
BepInEx/config/local.overlay.overlay_hud.cfg
```

Основные параметры:

| Секция и параметр | По умолчанию | Назначение |
| --- | ---: | --- |
| `Overlay.Endpoint` | `http://127.0.0.1:8787/api/monster-seen` | Endpoint встреченных монстров |
| `Overlay.LevelEndpoint` | `http://127.0.0.1:8787/api/level` | Endpoint смены уровня |
| `Detection.ScanIntervalSeconds` | `3` | Повторная попытка собрать roster при старте уровня |
| `Detection.StatusIntervalSeconds` | `10` | Страховочная полная синхронизация статусов |
| `Detection.RequireLineOfSight` | `true` | Показывать монстров только после встречи; `false` сразу раскрывает весь состав уровня |
| `Detection.RevealUnknownMonsters` | `false` | Сразу показывать монстров без собственной иконки — с заглушкой в виде четырёхконечной звезды; монстры со своими иконками появляются по обычным правилам |
| `Detection.PreferPlayerVisionDetection` | `true` | Использовать обнаружение через PlayerVision, когда оно доступно |
| `Debug.Logging` | `false` | Дополнительные диагностические строки в BepInEx-логе |
| `OverlayApp.AutoStart` | `true` | Автоматически запускать desktop-приложение |
| `OverlayApp.AutoClose` | `true` | Закрывать приложение при выходе из игры |
| `OverlayApp.ExecutableRelativePath` | пусто | Автоматический внешний путь для профиля BepInEx; либо пользовательский путь к EXE |
| `OverlayApp.ArchiveName` | `OverlayHUD_app.zip` | Имя комплектного архива приложения |

Известные старые значения пути по умолчанию автоматически заменяются пустым значением. Пользовательские пути сохраняют прежнее поведение: относительный путь считается от DLL, абсолютный используется напрямую; описанный внешний перенос к ним не применяется.

Значения `StatusIntervalSeconds` меньше `10` автоматически поднимаются до безопасного значения `10`. Обновление мода не сбрасывает сохранённые настройки: если ранее выставлено `RequireLineOfSight=false`, для обнаружения только после встречи измените его на `true`.

Цвет обводки обнаруженных монстров берётся из игровой категории `EnemyParent.difficulty`: 1 — зелёный, 2 — синий, 3 — красный. Если категория недоступна или некорректна, обводка золотая. Это действует и для известных, и для новых монстров. Если мод оставил игровую категорию по умолчанию, она считается первым уровнем.

Новые и модовые монстры используют `assets/monsters/new.webp` с золотистым бликом по рисунку раз в 8 секунд. HP и требуемая сила берутся из игровых компонентов для всех монстров, включая известных; статическая таблица силы больше не используется. Порог `grabForceNeeded.amount` пересчитывается в число улучшений силы для одного стоящего игрока с учётом `PhysGrabber.forceMax`, прочитанного из игры (в стандартных игровых ассетах — 6). Для групповой плитки показывается максимум доступных значений.

Игровой ресурс `Grab Force - Ungrabbable` отображается как «нельзя поднять», а не как огромное количество улучшений. Если данные недоступны, отображается `?`, без подстановки старого табличного значения. Число не гарантирует возможность захвата при временных запретах или изменённой модами механике; независимые от `EnemyParent`/`Enemy` системы врагов требуют отдельной поддержки.

Настройки интерфейса сохраняются отдельно от состояния забега и восстанавливаются после перезапуска EXE или игры. Синхронизация настроек не восстанавливает старых монстров, таймер и игровые значения. Уже потерянные до этого исправления настройки необходимо выставить заново.

ПКМ по значку OverlayHUD в трее открывает дополнительные действия:

- **Монитор** — выбор экрана при нескольких подключённых мониторах. Выбор сохраняется в `overlay-config.json` рядом с приложением; подключение и отключение экранов обрабатывается автоматически.
- **Язык / Language** — русский или английский язык оверлея и новых таймкодов. Выбор синхронизируется с языком в панели настроек оверлея и сохраняется между запусками.
- **Прочее** — показать или скрыть оверлей, включить **Взаимодействовать с оверлеем** или **Сохранять таймкоды**. Галочка взаимодействия означает, что оверлей принимает клики; без неё клики проходят в игру. Сохранение таймкодов по умолчанию включено; выбор сохраняется между запусками.
- **Сделать скриншот** — снимок текущего окна HUD на прозрачном фоне с выбором файла. Предлагаемое имя содержит местные дату и время без пробелов: `OverlayHUD_2026-10-12_21-04-05-006.png`. Игра и рабочий стол в снимок не попадают. Оверлей должен быть показан и загружен; включённая подложка HUD и открытые элементы управления остаются на снимке.

Аппаратное ускорение Electron включено по умолчанию. Через пункт **Аппаратное ускорение (перезапуск)…** в трее его можно отключать и включать. После подтверждения настройка сохраняется в `overlay-config.json`, и только приложение оверлея перезапускается; игра продолжает работать. Отмена не меняет настройку. Программный рендеринг может увеличить нагрузку на CPU.

При `OverlayApp.AutoClose=true` автоматически запущенный оверлей отслеживает процесс игры и закрывается после её выхода, в том числе после перезапуска при смене аппаратного ускорения. Для этого нужны обновлённые DLL плагина и desktop-приложение. На оверлей, запущенный вручную, это правило не распространяется.

Проверка процесса игры выполняется раз в секунду и работает также после краша игры. При начале закрытия оверлей даёт Electron 5 секунд на штатный выход, затем принудительно завершает собственное приложение. Отсутствие игровых данных не вызывает закрытие: пауза и загрузка не считаются выходом из игры.

Повторный запуск передаётся существующему экземпляру средствами Electron. Запуск из плагина с `AutoClose=true` привязывает его к игре, если у него ещё нет привязки или прежний процесс игры уже завершился. Привязка к работающей игре не заменяется. Поиск и уничтожение чужих процессов по имени или занятому порту не используются. Полностью зависший главный поток Electron не сможет выполнить внутренний таймер; такой экземпляр потребуется завершить через Диспетчер задач. Ранее установленное старое приложение также нужно закрыть вручную перед обновлением.

## Timestamps

Desktop HUD создаёт текстовые файлы в `timestamps/` рядом с `OverlayHUD.exe`. Путь по умолчанию:

```text
%LOCALAPPDATA%\OverlayHUD\profiles\<profile-key>\app\timestamps\YYYY-MM-DD_HH-MM-SS.txt
```

При пользовательском пути к EXE папка `timestamps/` по-прежнему находится рядом с ним. Путь timestamps Native HUD не изменён.

Пример строки:

```text
22:14:09 Уровень 42 SA [Смотритель, Гном x8, Главарь]
```

Язык новых строк соответствует языку оверлея: на английском тот же пример выглядит как `22:14:09 Level 42 SA [Peeper, Gnome x8, Headman]`. Названия локаций (`MoHA`, `HM`, `SA`, `MS`) не переводятся. Уже начатая строка завершается на том языке, на котором была создана.

Названия монстров берутся из официальных русской и английской таблиц `HUD` игры: например, `Snatcher` записывается как `Пони` / `Pony`. Плагин загружает обе таблицы независимо от выбранного языка игры и передаёт названия серверу. Пока таблицы недоступны, используется включённая в приложение копия названий, извлечённая из игровых пакетов локализации. Для этой синхронизации нужны обновлённые плагин и desktop-приложение. Старые файлы таймкодов не переписываются.

Неизвестные монстры и локации записываются исходными именами из игры, без перевода и сокращений. У названий локаций убирается служебный префикс `Level - `.

Галочка **Прочее → Сохранять таймкоды** отключает запись без удаления существующих файлов. При отключении текущая строка завершается; после повторного включения запись возобновляется со следующего уровня.

## Диагностика

Главный источник информации — свежий `BepInEx/LogOutput.log` из того профиля r2modman, через который действительно запускалась игра.

Полезные строки:

- `Loading [OverlayHUD ...]` — загруженная версия DLL;
- `Bundled OverlayHUD desktop app ready at:` — внешняя установка готова; далее указан фактический путь к EXE;
- `Extracted bundled OverlayHUD desktop app` — распаковка только для пользовательского пути установки;
- `Started bundled OverlayHUD desktop app` — `OverlayHUD.exe` запущен;
- `Registered spawned enemy parent` — враг зарегистрирован во внутреннем roster;
- `Marked monster for web overlay` — условие встречи с монстром сработало;
- `HTTP/1.1 200 OK` — локальный сервер принял обновление.

Если вместо прозрачного фона виден чёрный экран, снимите галочку **Аппаратное ускорение (перезапуск)…** в трее и подтвердите перезапуск оверлея. Альтернатива — указать `"hardwareAcceleration": false` в `overlay-config.json` и перезапустить приложение вручную. Для старых сборок обходной путь — запуск `OverlayHUD.exe --disable-gpu`.

Пустой список монстров не скрывает HUD: таймер, ценности и улучшения показываются и на уровнях без врагов. Повреждения и разрушение ценностей в комнате сдачи учитываются в потерях; штатная сдача предметов — нет.

Если HUD не появляется:

1. Проверьте, что игра запущена в windowed/borderless-режиме.
2. Проверьте путь к EXE из строки `Bundled OverlayHUD desktop app ready at:` и предупреждения о переносе/обновлении; для пользовательской установки — `OverlayApp.ExecutableRelativePath`. Архив `OverlayHUD_app.zip` должен оставаться рядом с DLL.
3. Убедитесь, что порт `8787` не занят другим процессом.
4. Временно включите `Debug.Logging = true`.
5. Приложите свежий `LogOutput.log` к отчёту об ошибке.

## КД монстров в мультиплеере

Для точного отсчёта у подключённого игрока обновлённый OverlayHUD должен быть установлен и у него, и у хоста. Хост раз в секунду передаёт таймеры через Photon только игрокам, объявившим поддержку протокола OverlayHUD. Отдельные серверы, порты и настройки не нужны; desktop-приложение обновлять для этой функции не требуется.

Клиент принимает данные только от текущего хоста, учитывает задержку доставки и сопоставляет монстров по сетевому ID. Получение таймера не раскрывает невстреченных монстров. При смене уровня, комнаты или хоста сетевые данные сбрасываются. Если у хоста нет поддержки синхронизации, клиент продолжает показывать состояние монстра без точного КД; случайный локальный таймер не используется.

Передача КД проверена пользователем в мультиплеере. Начиная с 26.11.2 хост также передаёт текущее и максимальное ХП: сразу после события урона и контрольным снимком раз в секунду. Клиент использует эти значения для полоски здоровья и цифр нанесённого урона. Это потеря ХП монстра от любых источников, а не персональный счётчик урона игрока. Для передачи ХП обновление требуется у хоста и клиентов; со старыми клиентами сохраняется передача КД. Синхронизацию ХП необходимо проверить в игровом лобби перед публикацией сборки.

## Ограничения

- Harmony-патчи и reflection зависят от внутреннего API R.E.P.O. и могут потребовать обновления после патчей игры.
- `EnemyOnScreen` работает не одинаково для всех типов врагов. Для `Tick` и `Upscream` используется узкий fallback через старую логику видимости/близости.
- Точность стоимости карты зависит от игровых событий ценностей и момента генерации уровня.
- OverlayHUD рассчитан на локальный desktop HUD и не является заменой полноценному OBS Browser Source для удалённого компьютера.

## Сборка из исходников

### Требования

- Windows;
- .NET SDK с поддержкой `net472`;
- установленная R.E.P.O. для Unity reference assemblies;
- Node.js и npm;
- BepInEx/Harmony reference assemblies.

Пути к Unity DLL сейчас заданы в `overlay-hud/OverlayHUD.csproj` через стандартный Steam-каталог. При другой установке игры измените `HintPath`.

### BepInEx-плагин

```powershell
dotnet build overlay-hud/OverlayHUD.csproj -c Release
```

Результат:

```text
overlay-hud/bin/Release/net472/OverlayHUD.dll
```

После сборки DLL нужно скопировать в:

```text
overlay-hud/package-flat/OverlayHUD.dll
overlay-hud/package/plugins/OverlayHUD/OverlayHUD.dll
```

### Electron-приложение

```powershell
cd game-overlay
npm install
npm run package
```

Результат:

```text
game-overlay/dist/OverlayHUD-win32-x64/
```

Сборка использует `--no-asar`: код приложения лежит в обычной папке `resources/app/`. Не включайте ASAR: Electron-менеджеры модов могут воспринимать `app.asar` как виртуальный каталог и выдавать `EBUSY` при удалении мода. Плагин поддерживает оба формата и автоматически переносит распознанную старую установку за пределы каталога мода; удалять её до переноса не нужно.

При создании `OverlayHUD_app.zip` перечисляйте верхнеуровневые файлы и каталоги явно. Архивация через `tar -C <dir> .` добавляет нежелательную запись `./`.

### Flat-пакет для локального импорта и Thunderstore

Flat-архив должен содержать ровно:

```text
icon.png
manifest.json
OverlayHUD.dll
OverlayHUD_app.zip
README.md
LICENSE
THIRD_PARTY_NOTICES.md
```

Перед публикацией проверяйте версию manifest, структуру обоих архивов и SHA-256 DLL во всех package-копиях.


**Обновление существующей установки:** закройте игру и OverlayHUD перед импортом. Сохраните старую папку `OverlayHUD_app` для автоматического переноса; изменение SHA-256 `OverlayHUD_app.zip` вызовет staged-обновление при desktop-автозапуске (см. «Перенос и обновление desktop-приложения»).
